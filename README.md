## 소개

**울산대 캠퍼스 길찾기**는 무거캠퍼스 안에서 두 건물 사이 가장 빠른 길을 찾아 주는 웹 서비스입니다.

카카오·네이버·구글 길찾기는 캠퍼스 안을 모릅니다. 차량 경로가 기본이고, 보행 경로를 준다 해도
학교 안쪽 보행로·계단·건물 사이 통로는 데이터에 없습니다. 정문에서 전기/컴퓨터공학관까지 찍으면
대학로를 따라 빙 도는 길이 나옵니다.

## 주요 기능

### 1. 캠퍼스 보행망 직접 구축
> 보행로도 계단도 지름길도, 학교 안 길을 통째로 들고 있어요.

- 노드 341개 (건물 42 · 장소 3 · 출입문 3 · 길목 293), 간선 492개 (차도 202 · 보행로 257 · 계단 33)
- 길 형상·건물 위치는 OpenStreetMap 실측 ([relation/9762419](https://www.openstreetmap.org/relation/9762419))
- OSM 이 **계단과 보행로를 따로 그려 놓고 안 물려 둔** 자리 12곳을 이어 붙였습니다.
  박물관 옆 계단은 차도에서 0.8m 떨어진 채 끊겨 있어서, 그대로 두면 길찾기가
  그 계단을 못 타고 150m 를 돌았습니다 (`scripts/mend-graph.mjs`)
- 건물은 가장 가까운 길목 **하나**에만 매달려 있었습니다. 그 하나가 건물 반대편에
  붙으면 코앞의 길을 두고 블록을 통째로 돕니다. 기초과학실험동은 북쪽 길목이 34m,
  남쪽이 36m 로 2m 차이였는데 북쪽만 잡혀서 조형관까지 119m 를 430m 로 갔습니다.
  **곧장 가면 코앞인데 그래프로는 한참 도는** 길목 30곳에 가닥을 더 맸습니다
- 그 문턱(세 배 이상 돌고 50m 넘게 줄어야)은 **계단에게 너무 높았습니다.** 계단은
  짧고, 어귀는 건물에서 30~50m 쯤 떨어져 있고, 돌아가는 길도 두 배 남짓인 자리가
  많습니다. 그래서 계단 33개 가운데 16개는 어느 경로에도 안 쓰였고, 문수관은 코앞
  계단을 두고 행정본관까지 308m 를 돌았습니다. **계단 어귀만 더 낮은 문턱으로 한
  번 더 훑어** 20곳에 가닥을 맸습니다. 문수관에서 행정본관은 176m 가 됐고, 곳곳을
  오가는 1128갈래 가운데 191갈래가 짧아졌습니다
- 어귀는 위아래 높이가 다른데 좌표만으로는 알 길이 없습니다. 잘못 잡으면 계단을
  타지 않고도 그 자리에 선 셈이 되어 길찾기가 평지로 빙 돕니다 — **빠르다면서 더
  걷습니다.** 그래서 가닥을 하나 놓을 때마다 곳곳의 길을 모두 다시 재서, 되레
  길어지는 데가 생기면 그 가닥을 도로 뺐습니다 (전컴관 둘레에서 2곳)
- 캠퍼스 안내도에 노란색으로 칠해 둔 **지름길 52개 구간**을 따로 표시
- 이진 힙 다익스트라. 간선 비용이 음수가 될 일이 없어 A\* 없이 충분

### 2. 세 가지 기준으로 비교
> 짧은 길과 빠른 길은 다릅니다. 아는 길은 또 다르고요.

- **최단거리** — 걷는 거리를 최소화
- **최소시간** — 바닥에 따라 같은 거리도 다르게 셈 (계단은 평지의 2.2배 + 진입 4초)
- **지름길 우선** — 표시된 지름길을 0.45배로 쳐서 아는 길로 붙임
- **건물은 목적지지 통로가 아닙니다.** 접속선은 건물 중심에서 곧게 이은 모형이라,
  두 가닥을 이어 붙이면 건물을 뚫고 가는 길이 됩니다. 건물 안을 정말로 가로지르는
  길은 `indoor` 면으로 따로 있습니다
- 시간만 세면 **4초 빠르다고 70m 를 더 걷는 길**이 이깁니다. 그래서 고를 때만
  1m 에 0.12초씩 얹어, 아슬아슬하게 이기던 우회로가 지게 했습니다
- 답이 다를 때만 다른 기준의 경로를 **주황 점선**으로 겹쳐 표시
- 지도 위에서 **초록은 가야 할 길 하나뿐**입니다. 배경 보행망은 회색 농담으로만
  말합니다 — 예전에는 둘 다 초록이라 어느 선을 따라가야 하는지 헷갈렸습니다
- 큰길로만 돌았을 때와 견줘 **몇 분을 벌었는지** 계산

### 3. 이름 · 번호 · 별명으로 찾기
> 7, 전컴관, ICT융합학부가 전부 같은 곳이에요.

- 목록에 오르는 곳 45개. 건물 번호는 캠퍼스 공식 안내도의 범례 그대로
- 좁은 화면에서는 **전체 화면 목록** — 검색, 번호순, 별칭, 현위치에서 몇 m
- **지도에서 고르기** — 시트를 내려 지도만 남기고, 근처 120m 안을 대충 눌러도 잡힘
- 넓은 화면에서는 칸 밑에 붙는 드롭다운

### 4. 실시간 따라가기
> 걸으면서 다음에 뭘 할지 한 줄만 보면 돼요.

- 위치를 경로 위로 끌어당겨 남은 거리·시간 계산
- 상단에 **다음 동작 하나만** 크게 — "80m 뒤 / 오른쪽으로 꺾기"
- 지나온 구간은 회색, 남은 길만 초록
- 지도가 현위치를 따라감. 배율은 처음 한 번만 맞추고 이후 손대지 않음
- 이탈 판정은 **35m 와 GPS 오차 반경의 1.5배 중 큰 쪽**
- 어림한 좌표(오차 50m 초과)로는 출발지를 잡지 않음. 지도에는 오차 반경을 원으로 표시

### 5. 폰에서는 화면이 단계마다 바뀜
> 손바닥만 한 화면에서 지도가 주인공이 되게.

| 단계 | 화면 |
|------|------|
| 고르는 중 | 시트가 펼쳐지고, 칸을 누르면 전체 화면 목록 |
| 지도에서 고르기 | 시트가 화면 밖으로 내려가고 지도만 |
| 경로 나옴 | 시트가 저절로 접혀 요약 한 줄만 |
| 안내 중 | 위쪽에 다음 동작, 지도는 현위치를 따라감 |

- 시트 손잡이를 끌어 접고 펴기. 접힌 높이는 손잡이 칸을 실제로 재서 사용
- 손으로 잡아 둔 시트 자리는 그 구간을 보는 동안만 유지

### 6. 가로로 돌리면 시트가 기둥이 됩니다
> 세로로 길 때와 가로로 납작할 때, 남는 자리의 모양이 정반대입니다.

세로로 든 폰은 위아래가 길어 아래에서 올라오는 시트가 맞습니다. 그대로 가로로
돌리면 높이가 390px 남짓이라 같은 시트가 화면의 3/4 을 물고, 지도에 90px 만
남습니다 — 캠퍼스가 한 줄로 눌립니다. 가로에서는 폭이 남으니 옆을 내줍니다.

| | 세로로 들었을 때 | 가로로 돌렸을 때 |
|--|------|------|
| 길찾기 패널 | 아래에서 올라오는 시트 | 왼쪽 기둥 (폭의 44%, 최대 330px) |
| 곳 고르기 | 전체 화면 목록 — 한 칸씩 | 전체 화면 목록 — 두 칸씩 |
| 상단 안내 띠 | 화면 맨 위 전체 폭 | 기둥을 비켜 오른쪽 |
| 지도에서 고르기 | 시트가 아래로 빠짐 | 기둥이 왼쪽으로 빠짐 |

- 갈림은 폭이 아니라 **높이 500px 과 화면 방향**으로 봅니다. 요즘 폰은 가로로
  들면 폭이 850px 을 넘어 폭만 보면 '넓은 화면' 으로 잡히기 때문입니다
- 폭에도 위(1024px)를 막아 둡니다 — 데스크톱에서 창을 낮게 눌러 놓은 것까지
  걸리면, 마우스로 쓰는 사람에게 전체 화면 목록이 튀어나옵니다
- 돌리면 보던 자리를 다시 맞춥니다. 손으로 넓혀 본 화면과 걷는 중인 화면은 둡니다
- 노치와 홈 바는 가로에서 좌우로 옵니다. `env(safe-area-inset-left/right)` 를 따로 챙깁니다

### 7. 첫 화면은 가볍게
> 캠퍼스 안 신호로도 한 번에 뜨게.

한글은 `-apple-system` 에도 `system-ui` 에도 글리프가 없어서 웹 글꼴로 떨어집니다.
그런데 Pretendard 원본은 2,008 KB 라, 느린 회선에서 글꼴이 도착하는 데 10초가
걸렸습니다. 페이지 무게 2,948 KB 중 대부분이 이것이었습니다.

- **빌드 타임 서브셋** — 소스와 캠퍼스 그래프에서 쓰는 글자 722자만 남겨 105 KB.
  굵기 축도 실제로 쓰는 400~700 으로 좁힘
- 유니코드 범위로 조각내는 **동적 서브셋은 안 씁니다.** 한글은 자주 쓰는 글자가
  코드 순서와 무관하게 흩어져 있어 짧은 문장 하나가 조각 여럿에 걸칩니다 —
  요청이 열 번으로 늘고, 조각을 가리키는 `@font-face` 92개짜리 CSS(49 KB)가
  렌더링까지 막습니다
- 빌드마다 다시 뽑습니다. 「모두에게 저장」으로 새 건물 이름이 들어와도 그 글자만
  글씨체가 달라지지 않게
- 자리는 Vite 에 맡깁니다. 이름에 해시가 붙어 내용이 바뀌면 주소도 바뀌므로,
  캐시를 끊으려고 사람이 판 번호를 챙길 일이 없습니다
- **`preload` 는 일부러 안 겁니다.** 걸어 보니 느린 회선에서 첫 그림이
  1,120ms → 1,720ms 로 되레 밀렸습니다 — 글꼴이 화면을 그리는 JS 와 대역폭을
  다투기 때문입니다. `swap` 이라 첫 그림은 어차피 대체 글꼴로 나갑니다
- 원본에 아예 없는 글자(`⇅ ⊕ ─ ◎`)는 스크립트가 일러 줍니다. 서브셋 탓이 아니라
  전부터 시스템 글꼴로 떨어지던 글자입니다

| 1.6Mbps · CPU 4배 감속 | 전 | 후 |
|--|--|--|
| 글꼴 도착 | 10,041 ms | 670 ms |
| 첫 방문 전송량 | 2,155 KB | 252 KB |

### 8. 시간표를 넣으면 다음 수업으로
> 다음에 어디로 가야 하고, 언제 나서야 하는가.

에브리타임에서 받은 시간표 그림을 올리면 수업 칸을 읽어 다음 수업까지 안내합니다.

- **강의실 코드가 시간표와 지도를 잇습니다.** 울산대 강의실은 `건물번호-호실`
  이고 그 번호가 캠퍼스 안내도 범례와 같아, `7-615` 가 곧 7번 전기/컴퓨터공학관
- 글자를 다 읽지 않습니다. 요일은 칸의 **가로 자리**, 시각은 **세로 자리**에
  적혀 있어 읽어야 하는 것은 강의실 코드 하나입니다
- **과목 이름은 안 가져옵니다.** 인식이 절반쯤밖에 안 맞아 「창업아이디어설계」가
  「창」으로 들어왔습니다. 큰 언어 데이터(6.6MB)로도 정확도가 그대로여서 더 받아서
  될 일도 아니었습니다. 어디로 가느냐는 강의실 하나로 정해집니다
- 시각은 **정각으로 맞춥니다**. 수업은 교시로 돌아가므로(1교시 9시, 6교시 14시)
  그림에서 잰 몇 분의 어긋남을 들고 다닐 이유가 없습니다
- **읽은 값을 그대로 쓰지 않습니다.** 확인 화면에서 보고 고친 뒤에야 시간표가
  됩니다 — 틀린 강의실로 엉뚱한 건물을 안내하는 것보다 낫습니다
- **나갈 시각은 걷는 시간만으로 못 셈합니다.** 지도는 건물 중심까지만 데려다
  주는데 `7-615` 는 6층입니다. 호실 번호가 층을 알려 주므로 문 앞 1분 + 층당
  25초를 얹습니다
- 인식기는 **쓸 때만** 내려받습니다(약 5MB). 첫 화면에는 안 걸립니다
- 시간표는 **이 브라우저에만** 남습니다. 누가 몇 시에 어디 있는지는 남한테 줄
  값이 아니라, 서버로도 통계로도 안 보냅니다

### 9. 설치 없이, 끊겨도
> 캠퍼스 안은 신호가 잘 죽어요.

- 로그인·설치 없이 브라우저에서 바로
- 홈 화면에 추가하면 앱처럼 (PWA). iOS는 안내 문구로 대체
- 서비스 워커가 앱 껍데기와 한 번 본 지도 타일 500장을 캐시
- 그래프는 번들에 들어 있어 애초에 네트워크를 안 탐

### 10. 편집 모드
> 틀린 곳은 그 자리에서 고쳐요.

- `?edit=1` — 지점 추가, 종류(건물·시설·출입문·길목) 지정, 좌표 끌어 맞추기
- 좌표 신뢰도(`근사치` / `맞춘 좌표`)를 직접 표시
- 길 잇기, 바닥·지름길·비 가림 지정
- 길에 안 이어진 곳은 그 자리에서 경고
- **모두에게 저장** — 암호를 확인하고 저장소에 커밋 → 재배포 → 모두에게 반영

### 11. 통계
> 어디서 어디로 다니는지 알아야 고칠 자리가 보여요.

- Google Analytics 4. 측정 ID가 없으면 **번들에서 통째로 빠짐**
- `route_missing` — 길이 없다고 끝난 조합. 그래프에 빠진 길이라는 신호
- 좌표와 위치 기록은 보내지 않음. 추적 거부(DNT·GPC) 존중

## 기술 스택

| 구분 | 기술 |
|------|------|
| UI | React 19, TypeScript |
| 스타일 | vanilla-extract (제로 런타임 CSS-in-TS) |
| 지도 | Leaflet 1.9, OpenStreetMap 타일 |
| 길찾기 | 직접 구현 (이진 힙 다익스트라) |
| 빌드 | Vite 8, pnpm |
| 글꼴 | Pretendard — subset-font 로 빌드 타임 서브셋 |
| 글자 인식 | Tesseract.js (한국어만, 쓸 때만 내려받음) |
| 서버 | 없음 (정적 파일). 저장 기능만 Vercel 서버리스 함수 1개 |
| 배포 | Vercel |
| 데이터 | Overpass API → 시드 스크립트 → campus.json |

```
campus-route/

│   └── publish.ts                # 고친 지도를 저장소에 커밋 (유일한 서버 코드)
```

## 아키텍처

```
┌──────────────────┐
│      View         │  React 컴포넌트 + Leaflet
├──────────────────┤
│      State        │  App.tsx 한 곳에서 화면 단계를 결정
├──────────────────┤
│     Routing       │  다익스트라 · 시간 모형 · 진행 추적 (전부 브라우저)
├──────────────────┤
│      Data         │  campus.json (번들) ← 편집분은 localStorage 가 덮어씀
└──────────────────┘
```

서버가 없습니다. 그래프는 빌드할 때 번들에 박히고, 길찾기는 사용자 기기에서 끝납니다.
편집한 내용은 그 브라우저에만 남고, 「모두에게 저장」을 눌러야 저장소로 올라갑니다.

## 데이터 출처

| 무엇 | 어디서 |
|------|--------|
| 길 형상 · 건물 위치 | OpenStreetMap ([ODbL](https://www.openstreetmap.org/copyright)) |
| 계단 · 터널 · 지하 통로 | OSM `highway=steps`, `tunnel`, `covered` 태그 |
| 건물 번호 · 별칭 | 캠퍼스 공식 안내도 범례 (사람이 얹은 유일한 값) |
| 지름길 52개 구간 | 안내도에 노란색으로 칠해 둔 길 |
| 마스코트 울리니 | 울산대학교 [마스코트 캐릭터](https://www.ulsan.ac.kr/kor/CMS/Contents/Contents.do?mCode=MN356) — 시간표 창의 빈 화면에 씁니다 |

건물 좌표는 출입구가 아니라 **건물 중심**입니다. 짧은 경로일수록 오차 비율이 큽니다.

울산대학교의 UI 와 마스코트 캐릭터는 상표권 등 지식재산권의 보호를 받는 대학의 공식
자산입니다. 이 프로젝트는 **비영리 학생 프로젝트**로서 공식 가이드라인에 따라 크기만
비례 그대로 조정해 쓰고 있으며, 형태·굵기·비례는 손대지 않았습니다. 상업적 이용에는
대학의 사전 승인이 필요합니다.
